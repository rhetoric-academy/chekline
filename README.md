# فاحص الروابط للفريق

أداة فحص روابط تعمل على **Cloudflare Worker واحد** (واجهة + فحص + سجل)، وكودها على GitHub.

- تفحص كل رابط: يعمل / يعمل بعد تحويل / الموقع موجود والصفحة مفقودة / ممنوع / خطأ خادم / حلقة تحويل / مهلة / نطاق غير موجود / مشكلة SSL
- تعرض سلسلة التحويلات خطوة بخطوة (اضغط على النتيجة)
- المستخدم يكتب اسمه فقط مرة واحدة، بلا تسجيل دخول
- سجل للمالك في `/admin` مع بحث وتصفية وتصدير CSV
- تسجّل الفحوصات في الخلفية دون إشعار في الواجهة، وتحذف السجل تلقائياً بعد 90 يوماً، وتحذف الاستعلام (`?token=…`) قبل الحفظ

---

## خطوات النشر من الصفر (نحو 15 دقيقة)

### 1) حساب GitHub
أنشئ حساباً على https://github.com إن لم يكن لديك.

### 2) مستودع جديد
1. اضغط **+** أعلى الصفحة ثم **New repository**.
2. الاسم: `link-checker`.
3. اختر **Private** (موصى به لأن الأداة خاصة بفريقك).
4. فعّل **Add a README file** ثم **Create repository**.

### 3) رفع الملفات
1. داخل المستودع: **Add file ← Upload files**.
2. اسحب `worker.js` و`wrangler.toml` (لا ترفع هذا الـ README إن كان عندك README).
3. اضغط **Commit changes**.

### 4) حساب Cloudflare
أنشئ حساباً مجانياً على https://dash.cloudflare.com/sign-up. لا تحتاج بطاقة ولا نطاقاً خاصاً.

### 5) إنشاء مخزن السجل (KV)
1. من القائمة اليسرى: **Storage & Databases ← KV** (أو **Workers & Pages ← KV**).
2. **Create** واكتب الاسم `link-checker-logs` ثم **Add**.
3. انسخ **Namespace ID** (نص طويل من أحرف وأرقام).

### 6) وضع المعرّف في الإعداد
1. في GitHub افتح `wrangler.toml` ← أيقونة القلم ✏️.
2. استبدل `ضع_هنا_معرّف_KV` بالمعرّف الذي نسخته (يبقى بين علامتي الاقتباس).
3. **Commit changes**.

### 7) ربط المستودع بـ Cloudflare
1. **Workers & Pages ← Create ← Import a repository** (أو **Connect to Git**).
2. اربط حساب GitHub واسمح بالوصول للمستودع `link-checker` فقط.
3. اختر المستودع ثم **Next**.
4. **Project name**: اكتب `link-checker` (يجب أن يطابق `name` في wrangler.toml).
5. اترك **Build command** فارغاً، وأبقِ **Deploy command** كما هو (`npx wrangler deploy`).
6. اضغط **Save and Deploy**، وانتظر دقيقة حتى يكتمل البناء.

### 8) الأسرار
في **Workers & Pages ← link-checker ← Settings ← Variables and Secrets ← Add**، اختر النوع **Secret**:

| الاسم | القيمة | مطلوب؟ |
|---|---|---|
| `ADMIN_KEY` | كلمة سر طويلة لصفحة السجل | نعم |
| `TEAM_KEY` | رمز يعرفه الفريق ليدخلوا به | اختياري، لكنه يمنع الغرباء من استخدام أداتك |

اضغط **Deploy** بعد الحفظ.

### 9) التجربة
1. افتح `https://link-checker.<حسابك>.workers.dev` (الرابط يظهر في صفحة الـ Worker).
2. اكتب اسمك ثم افحص:
   ```
   google.com
   http://github.com
   https://example.com/no-such-page
   no-such-domain-12345.com
   ```
3. يجب أن ترى: يعمل، ثم يعمل بعد تحويل، ثم الصفحة مفقودة، ثم النطاق غير موجود.
4. افتح `/admin` وأدخل `ADMIN_KEY` لترى السجل.

### 10) مشاركة الرابط
أرسل رابط الـ Worker لفريقك (ومعه `TEAM_KEY` إن فعّلته).

## التحديث لاحقاً
عدّل أي ملف في GitHub ← Commit، فيُنشر التحديث تلقائياً.

## الحدود في الخطة المجانية
- 100 ألف طلب يومياً.
- نحو **1000 فحص مسجّل يومياً** (حد كتابة KV). عند تجاوزه يستمر الفحص لكن لا يُسجَّل.
- عنوان `workers.dev` عام، فاستخدم `TEAM_KEY` لتقييد الاستخدام.

## ملاحظات
- الفحص ينطلق من خوادم Cloudflare، وبعض المواقع تحجب هذه العناوين فتظهر "ممنوع". وهذا لا يعني أن الرابط معطل في متصفحك.
- مسار الرابط (قبل `?`) يُحفظ في السجل. إن كان فريقك يلصق روابط يكون الرمز السري فيها جزءاً من المسار، فعدّل دالة `clean` في worker.js لتحفظ النطاق فقط.
- الروابط المحلية والعناوين الداخلية (`localhost` و`192.168.x.x` …) تُرفض.

## حل المشكلات
| المشكلة | الحل |
|---|---|
| فشل البناء بسبب KV | تأكد أن المعرّف في `wrangler.toml` صحيح وبلا مسافات |
| فشل البناء بسبب الاسم | اجعل Project name مطابقاً لـ `name` في wrangler.toml |
| `/admin` يقول المفتاح غير صحيح | تأكد من إضافة `ADMIN_KEY` كـ Secret ثم Deploy |
| السجل فارغ | تأكد من ربط KV باسم `LOGS` بالضبط |
